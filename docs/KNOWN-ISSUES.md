# 已知限制与贡献方向

Local300 v0.12是未完成的本地测试项目。本页区分已经验收的修复、仍未完成的范围和适合贡献的任务；列入任务不表示已经开始实施。

## 当前可以依赖的验收范围

以下是用户对特定版本与操作的实际确认，不扩大为全部玩法通过：

- 亚瑟王倒计时结束后能够进图；敌方在既定时间入场后，TAB及正常结算能显示参战英雄。
- 当前一件装备的宝石能够一键全部摘除；不是清空全部装备或全部方案。
- 模拟充值后钻石即时显示正常；黑岩持续移动、普攻和 Q测试中没有再出现此前的卡死与自身模型替换。
- 许愿、小保底、大保底区域显示正常；批量强化入口和开始／停止正常。
- GM邮件附件已通过实际客户端领取；已读不等于已领取，修复保留了原资产和重复领取校验。
- v0.12启用客户端保护后可正常进入大厅；普通停服后保护继续阻止更新器外连。

这些修复的经验已反映在源码与协议约定中。若同类问题重新出现，请提供新版本和可复现步骤，不要先清空数据、补发物品或重新初始化账号。

## 尚未完整实现或验证

| 范围 | 当前事实与限制 |
| --- | --- |
| 英雄 | 默认战斗行为只注册黑岩射手与亚瑟王。亚瑟已有基础模块和部分技能修正，但技能与表现仍未完成、未经全量验收；不应理解为完全没有技能代码。账号拥有更多英雄不代表能在战场使用这些英雄。 |
| 战场模式 | 当前公开测试围绕地图252及进入后第10、30、50秒出现的三名敌方假人。不是完整 PvP、AI、7v7或所有地图的实现。 |
| 装备、神赐、魔导器 | 目录、名称、配置或客户端说明存在，不代表所有主动、被动、子状态与视觉效果均已接入。需要逐项覆盖表，不能笼统标为全部完成。 |
| 计分与终局规则 | 内塔400分在源码中明确标为暂定规则；助攻等细节仍有待取证。计时和计分显示可用，不代表所有原服终局条件已经还原。 |
| 对局收益 | `battle-match-stats.js`将连杀奖励、账号经验、账号货币奖励和勋章标为未支持。结算面板出现不等于这些收益已经实现。 |
| 视觉与手感 | 需要继续核对具体技能、子状态、伤害浮字、建筑范围显示和高密度单位的移动表现；协议编码正确不能替代原生画面与手感验证。 |
| 新号 | 公共工具使用已准备的本地初始种子；完整原生从零建角不是本次发布已验收的能力。不要以清空大部分角色帧代替完整初始化。 |
| 客户端更新 | 修改服务端版本号只是尝试连接新客户端，不能证明协议、资源和玩法兼容。原生启动参数只对已核对版本有证据，新版需重新检查。 |
| 原服恢复 | v0.12已有文件恢复测试与保护规则检查；本轮没有再次实测完整的原生回原服登录流程。地址恢复不恢复已更新的客户端资源。 |
| 平台与环境 | 当前发行目标为 Windows10/11 x64。全新电脑和干净开发环境仍待独立验证；不承诺其他系统可运行启动器。 |

## 建议优先贡献的任务

### 1. 开发环境与合成测试

在干净 Windows 环境验证资料导入、缺失依赖提示、构建与测试步骤，记录工具版本和结果。构造不依赖真实账号、抓包或个人路径的最小测试。不要通过上传运行资产或存档使测试变绿。

可交付物：可复现的环境说明、资料缺失时的准确诊断、独立合成夹具，以及源码导出目录中的验证结果。

### 2. 客户端兼容矩阵

按客户端 SHA-256记录登录、邮件、符文、进图、技能和恢复等分项结果。检查报文长度、字段与原生门控；发生更新时先确认目标字节，不替换旧报告的哈希就宣称重新验证。

可交付物：脱敏的版本矩阵、可复算的协议结论、对应合成测试。不得附原版 EXE、原始帧或账号日志。

### 3. 英雄与战场行为

先为一个英雄或一条机制界定范围，再使用现有行为钩子接入。保留移动、控制、冷却、死亡复活、来源生命编号及观察者视野的约束。新增英雄不能借用另一名英雄的原生技能编号假装完成。

可交付物：单机制规则与证据、状态生命周期测试、原生表现待验清单。开始大范围英雄扩展或玩法还原前应另开明确议题。

### 4. 装备与养成覆盖表

分别登记“已接入并验证”“仅有数据”“未实现”“参数缺证”“待原生表现验收”。优先解决可复现问题，再扩展范围。对随机规则、距离单位、叠加顺序和原生技能绑定逐项取证，不能统一猜值。

### 5. 计分、收益与故障恢复

补齐暂定规则的证据，明确新收益的结算时机、领取归属和重复处理。故障测试需覆盖写前失败、部分提交、断开、重复请求和正常重启，证明不丢资产、不重复发放。

### 6. 客户端保护与恢复

增加不同 Windows策略和客户端版本的验证。保持规则仅作用于选定路径及本工具拥有的条目，保留本机连接。撤销、移动目录、取消权限、规则冲突与恢复备份分别测试，不能为处理失败修改全局防火墙策略。

## 报告问题需要什么

请说明工具版本、客户端版本与 SHA-256、具体步骤、发生时间、预期和实际结果，以及是否能够重复。界面问题可附不含个人信息的截图。诊断材料只提供与问题有关的脱敏片段；不要上传密码、摘要、硬件信息、控制令牌、原始抓包、整个日志目录或存档。

库存变化应先核对实际操作与时间线；显示异常应分别检查持久化状态和客户端刷新。未经确认不要回滚、补发或删除 pending记录。协作方式见 [CONTRIBUTING](../CONTRIBUTING.md)，协议材料格式见 [PROTOCOL-CONTRIBUTIONS](PROTOCOL-CONTRIBUTIONS.md)。
