# v0.12 源码协作副本的验证范围

整理于2026-10-15。源码基线来自已验收v0.12的272份生产JavaScript模块，以及启动器和保护组件的C#源码。两份数据目录模块中的17处本机资料来源路径改为不包含个人目录的相对描述；其他运行逻辑沿用基线。17个历史路径下的兼容JS只作为生产依赖保留，不公开相应研究记录。

## 已完成

- 源码边界检查：排除本地生成目录，检查链接、禁止类型、常见凭据模式和JavaScript语法；保留的兼容模块使用准确白名单。
- 维护者在仓库外核对已知原登录名、角色名、登录摘要、平台字段及个人路径：未在公开候选源码中发现对应残留。私人参考值与扫描输入不放进仓库；这不是对所有未知字段的语义证明。
- 28项Node测试：客户端配置备份恢复及资源工具输入验证。
- 16项资源助手纯合成检查、14组防火墙策略模拟测试；这些测试不启动真实游戏或更改真实防火墙。
- 只读导入固定版本EXE的139份本地运行资料，逐项核对清单、大小和SHA-256。
- 两次重新构建的内嵌资料包字节相同；272份生产JS以可编辑明文嵌入，未夹入脚本封装器、实际存档或源工作区历史。
- 重建后台使用随机回环端口、独立账号目录和合成客户端完成启动、版本握手、GM充值请求、正常保存、重启及配置逐字节恢复。没有运行真实客户端，也没有操作已有服务。

## 仍需分别验证

原发行v0.12的玩家画面验收与源码协作版的新构建不是同一个EXE。本次没有把新构建的GUI和全部玩法再做一轮原生画面复测；发行版的已确认范围见[已知问题](KNOWN-ISSUES.md)。

旧.NET编译器可能使重复编译的外层EXE字节不同，因此“可构建”不等于“能得到与原发行版相同的EXE哈希”。源码公开版默认不附原图标、也不做旧脚本封装，外层产物本来就会不同。

尚未在另一台全新Windows机器上独立验证开发工具链，完整原生回原服流程本轮也未再次实测。客户端版本号、系统策略、第三方防火墙及未来协议变更仍需要单独记录兼容结果。

新增或修改源码后，应重新运行适当测试，不能使用本页作为新字节已经验证的证明。
